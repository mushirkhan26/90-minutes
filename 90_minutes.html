1 Project Overview

2 Architecture Pattern (BLoC)

The project follows a Clean Architecture with BLoC pattern, ensuring high maintainability and testability. The code is organized by features, each containing its own BLoCs, Repositories, and UI components.

lib/ ├── config/ # App configuration & routing ├── core/ # Shared logic & infrastructure │ ├── api/ # Networking layer (Dio/Http) │ ├── bloc/ # Global/shared BLoCs │ ├── constants/ # Theme & App constants │ ├── errors/ # Failure & Exception handling │ └── tracking/ # Real-time location logic │ ├── features/ # Module-based features │ ├── auth/ # Mobile Login & Signup (Unified) │ ├── home/ # Category-based discovery (Men/Women/Kids) │ ├── search/ # Smart product search │ ├── cart/ # Cart management & Checkout │ ├── wishlist/ # Saved items │ ├── profile/ # User account & settings │ └── tracking/ # Live order status tracking │ └── widgets/ # Reusable UI components
BLoC Workflow: UI dispatches an Event → BLoC processes business logic via Repository → BLoC emits a State → UI rebuilds based on the State.

4 Networking / API Layer

🌐 REST API (Dio)

  • Client: Dio for interceptors & performance
  • Auth: Bearer Token injection
  • Automatic Retries & Error Mapping
  • Multipart support for Profile Image

🔌 Socket.IO

  • Live Delivery Tracking
  • Order Status Push Updates
  • Low-latency real-time events
  • Automatic reconnection handling

5 Real-Time Communication (Tracking)

Real-time location tracking allows customers to see the delivery partner's movement on the map within 90 minutes.

LocationService → Handles Google Maps / Mapbox integration ↓ SocketManager → Listens to 'rider_location_update' event ↓ TrackingBloc → Updates UI with Lat/Lng coordinates
