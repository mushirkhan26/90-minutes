1 Project Overview

HrZ_hrms is a production-grade Human Resource Management System (HRMS) mobile application built with Flutter. It serves as an internal employee portal for organizations, supporting real-time chat, leave management, attendance tracking, internal mail, meetings, and more.

2 Architecture Pattern

The project follows a Feature-First Clean Architecture with a clear separation of concerns across 4 top-level layers.

lib/ ├── config/ # App-wide configuration │ ├── navigation/ # GoRouter setup + route constants │ └── theme/ # AppTheme (light mode) │ ├── core/ # Shared infrastructure │ ├── api/ # HTTP layer (ApiHelper + services) │ ├── constants/ # AppConstants (URLs, sizes, durations) │ ├── errors/ # Custom exceptions + error screen │ ├── models/ # 12 shared data models │ ├── services/ # Storage, notifications, logging │ ├── socket/ # Real-time socket layer │ └── utils/ # Utility helpers │ ├── features/ # 12 feature modules │ ├── auth/ # Login, OTP, password, NDA, onboarding │ ├── chat/ # 1-on-1 & group chat │ ├── complaint/ # Complaint management │ ├── holiday/ # Holiday calendar │ ├── home/ # Dashboard, attendance clock-in/out │ ├── hr_services/ # Resignation │ ├── leave/ # Leave requests & admin approval │ ├── mail/ # Internal mail system │ ├── meet/ # Meeting scheduling │ ├── settings/ # Permissions screen │ ├── social/ # Social hub / posts │ └── tasks/ # Task management │ └── widgets/ # Global reusable widgets

Each feature follows an internal Provider → Service → ApiHelper pattern:

Screen (UI) → Provider (state) → Service (API calls) → ApiHelper (HTTP) → Backend

4 Networking / API Layer

🌐 REST API

  • Package: http: ^1.5.0
  • Base URL: AWS API Gateway
  • Region: us-east-1
  • Auth: Bearer JWT token
  • Methods: GET, POST, PUT, PATCH, DELETE

🔌 Socket Server

  • Package: socket_io_client ^3.1.2
  • Host: Render.com
  • URL: hrms-socket.onrender.com
  • Protocol: Socket.IO (WebSocket)
  • Auto-reconnect on disconnect

ApiHelper — Generic HTTP Client

A single ApiHelper class wraps all HTTP calls with automatic token injection, request/response logging, and error handling:

5 Real-Time Communication (WebSocket)

A 3-layer socket architecture separates connection management, event abstraction, and UI state:

SocketService (singleton) → Raw socket.io connection + reconnect logic ↓ SocketManager (singleton) → Emit/listen event abstraction ↓ SocketProvider → 1-on-1 chat UI state (ChangeNotifier) GroupSocketProvider → Group chat UI state (ChangeNotifier)

6 Storage Strategy

The app uses a 3-tier local storage strategy — no on-device SQL/NoSQL database. All persistent data lives on the backend; local storage is purely for caching and session management.

Tier 1 — SecureStorageService (Encrypted)

Package: flutter_secure_storage: ^9.2.4 — stores sensitive data in the OS keychain/keystore.

KeyData
auth_tokenJWT Bearer token
employee_idLogged-in employee ID
username, email, roleUser identity fields
app_tokenFCM push notification token
mobile, alter_mobile, gender, address, profile_imageProfile fields
nda_submitted, onboarding_completedOnboarding flags

Tier 2 — LocalStorageService (JSON Cache)

Package: shared_preferences: ^2.5.3 — stores non-sensitive cached data as JSON strings.

KeyDataTTL
employee_listFull employee list (JSON array)1 hour
chat_messages_{conversationId}Messages per conversationPersistent
group_chatsGroup chat listPersistent
group_messages_{groupId}Messages per groupPersistent
meet_listMeeting listTimestamped
inbox_mails, sent_mails, trash_mailsMail cacheTimestamped
leave_history, available_leaveLeave dataPersistent
attendance_dataAttendance recordsPersistent
recent_chatsOrdered list of recent chat user IDsPersistent
is_logged_inBoolean login flagSession

Tier 3 — Remote Backend Database

The backend (AWS + Render) manages the actual persistent database. The app treats it as the source of truth and caches locally for offline access and performance optimization.

7 Push Notifications

A dual notification system handles both remote (FCM) and local notifications:

☁️ Firebase Cloud Messaging

  • Package: firebase_messaging ^16.0.3
  • Handles background + terminated state
  • FCM token synced to backend on login
  • Token auto-refreshes on change

  • Package: flutter_local_notifications ^19.5.0

  • Consolidated chat badge (e.g. "3 unread")

11 Authentication Flow

── LOGIN FLOW ────────────────────────────────────────────── 1. User enters employeeId + password 2. POST /employee/login 3. JWT token → SecureStorageService (auth_token) 4. FCM token synced → backend (employee/profile/:id) 5. Socket joined (userId + username) 6. Navigate based on flags: ndaSubmitted = false → /nda onboardingCompleted = false → /onboarding else → /home ── FORGOT PASSWORD FLOW ──────────────────────────────────── 1. GET /employee/getOTP/:employeeId 2. POST /employee/verifyOtp { employeeId, otp } 3. POST /employee/changePassword { employeeId, password } ── SESSION RESTORE ───────────────────────────────────────── 1. App start → LocalStorageService.isLoggedIn() 2. If true → SecureStorageService.getUserData() 3. AuthState.authenticated → navigate to /home ── LOGOUT FLOW ───────────────────────────────────────────── 1. SocketManager.leave() → disconnect socket 2. SecureStorageService.clearUserData() 3. LocalStorageService.setLoginState(false) 4. Navigate to /login

14 Architecture Diagram

┌─────────────────────────────────────────────────────────────┐ │ Flutter App (UI Layer) │ │ Screens → Widgets → Providers (ChangeNotifier) │ └──────────────────────┬──────────────────────────────────────┘ │ ┌────────────┴────────────┐ │ │ ┌─────────▼──────┐ ┌────────▼────────┐ │ REST API │ │ WebSocket │ │ (http pkg) │ │ (socket_io) │ │ ApiHelper │ │ SocketManager │ └─────────┬──────┘ └────────┬────────┘ │ │ └────────────┬────────────┘ │ ┌────────────▼────────────┐ │ Backend Services │ │ AWS API Gateway (REST) │ │ Render.com (Socket.IO) │ └─────────────────────────┘ Local Storage (3-Tier): SecureStorage (encrypted) → JWT, FCM token, profile data SharedPreferences (JSON) → Messages, mails, employees, meets Remote Backend DB → Source of truth (all persistent data) Push Notifications: FCM (Firebase) → Background / terminated state flutter_local_notifications → Foreground in-app notifications Auth State Machine: idle → loading → authenticated → unauthenticated / error
Note: The app uses keys.env (flutter_dotenv) for environment configuration. Ensure this file is present and not committed to version control. The socket server on Render.com may have cold-start delays (~30s) after inactivity.
